# Аналитика Telegram-канала @krylikryli (Крыли)

Анализ вовлечённости Telegram-канала **@krylikryli** за 12 месяцев: сбор данных, ETL в PostgreSQL, витрины, визуализации и статистическая проверка гипотез.

---

## 📌 О проекте

**Цель:** понять, какие факторы влияют на вовлечённость аудитории (ER), и дать 3 практических рекомендации с подтверждающими цифрами.

| Параметр | Значение |
|---|---|
| Канал | @krylikryli (Крыли) |
| Период | 13.10.2025 — 08.10.2026 (12 месяцев) |
| Объём данных | 1 480 публикаций; в витринах — 1 435 (без 45 «свежих») |
| Основная метрика | **ER** = (реакции + ответы + форварды) / просмотры |
| Язык | Python 3.14 |
| БД | PostgreSQL 16 (Docker) |

Чтение переменных в ноутбуках/скриптах через `python-dotenv`:

```python
import os
from pathlib import Path
from dotenv import load_dotenv
from sqlalchemy import create_engine

# подхватываем .env из корня проекта
load_dotenv(Path.cwd().parent / ".env")  # в ноутбуке из notebooks/; из корня — load_dotenv()

database_url = os.getenv("DATABASE_URL")
if not database_url:
    raise RuntimeError("DATABASE_URL не задан — проверьте .env")

engine = create_engine(database_url, future=True)

# убедимся, что драйвер превратил URL в маскированную строку без пароля
print(engine.url.render_as_string(hide_password=True))
```

Тот же паттерн применяется в `etl/load_telegram.py` для `TG_API_ID`, `TG_API_HASH`, `TG_CHANNEL`:


## 🗄️ Схема данных

### Слои

| Слой | Таблица(ы) | Описание |
|---|---|---|
| Raw | `raw_posts` | сырые посты из Telegram API |
| Cleansed | `cleansed_posts` | очищенные, с расчётными полями (ER, hour, weekday, flags) |
| Marts | `mart_by_*` | агрегаты для аналитики |

### Витрины `mart_*`

| Витрина | Разрез | Строк |
|---|---|---:|
| `mart_by_hour` | по часу публикации | 24 |
| `mart_by_weekday` | по дню недели | 7 |
| `mart_by_content_type` | по типу медиа | 3 |
| `mart_by_text_flags` | по текстовым признакам | — |
| `mart_by_interval` | по интервалу между постами | — |
| `mart_by_text_length` | по длине текста | — |
| `mart_by_combination` | тип × часть дня | 8 |

> Шесть основных витрин содержат по **1 435** публикаций (отфильтрованы «свежие» посты моложе 7 дней — чтобы метрики «дозрели»).

### Расчётные поля в `cleansed_posts`

- `er` — engagement rate (реакции + ответы + форварды) / просмотры
- `er_norm` — ER, нормированный к медиане канала
- `reactions_per_view`, `replies_per_view`, `forwards_per_view`
- `hour`, `weekday`, `part_of_day` (night/morning/day/evening)
- `text_length`, `length_bucket`, `length_tertile`
- `time_since_prev_post` — интервал с предыдущим постом (в часах)
- `is_recent`, `is_holiday`, `is_pinned`, `is_forwarded`, `is_personal_heur`

## 📊 Ключевые цифры

**Общие показатели:**

| Метрика | Среднее | Медиана |
|---|---:|---:|
| Просмотры | 2 286 | 2 026 |
| Реакции | 5,7 | 2 |
| Ответы | 7,3 | 2 |
| Форварды | 8,2 | 4 |
| ER | 0,93 % | 0,65 % |

> ⚠️ **Среднее ER (0,93 %) выше медианы (0,65 %)** — распределение вытягивают единичные вирусные посты. Решения принимаем по **медиане**.

**Три главных вывода:**

1. **Личный контент — сильнейший фактор.** Медиана ER вдвое выше промо (1,25 % vs 0,64 %, Mann-Whitney p < 0,001); в регрессии +0,79 к log(ER) (p < 0,001).
2. **Утро (07:00–11:00) — лучшее окно.** ANOVA p = 0,00004; утренний коэф. +0,24 (p = 0,001); ER 1,18–1,34 % против медианы 0,65 %.
3. **Текст сильнее фото.** Текст без медиа: ER 1,17 %; фото: 0,79 % (разница ~48 %). Длина текста коррелирует с ER положительно (rho = 0,38).

## 🧪 Статистические методы (Часть 3)

| Метод | Что проверяем | Результат |
|---|---|---|
| **Spearman** | связь признаков с ER | 5 из 7 связей значимы после FDR |
| **Mann-Whitney U** | личные vs промо | U = 45 596, p < 0,001 → значимо |
| **ANOVA** | ER по частям дня | F = 7,735, p = 0,00004 → значимо |
| **FDR (Benjamini-Hochberg)** | поправка на множественные сравнения | — |
| **OLS-регрессия** | вклад факторов на log(ER) | личный +0,79; утро +0,24; вечер +0,20 |

**Корреляции Spearman с ER (после FDR):**

| Фактор | rho | p_adj | Значимо? |
|---|---:|---:|---|
| Ответы (replies) | 0,708 | 0,000 | ✅ |
| Реакции | 0,674 | 0,000 | ✅ |
| Форварды | 0,435 | 0,000 | ✅ |
| Длина текста | 0,376 | 0,000 | ✅ |
| Интервал с прошлым постом | 0,240 | 0,000 | ✅ |
| Просмотры | −0,037 | 0,191 | ❌ |
| Час (hour) | 0,023 | 0,385 | ❌ |

⚠️ **Важный нюанс:** «час» как непрерывная переменная **не значим** (rho = 0,023, p = 0,385), но **часть дня — значима**. Дело не в «магическом часе», а в блоке суток.

## ⚠️ Ограничения анализа

1. **Выборка ~1 435 постов** — отдельные группы малы (личные ночью — 3 поста).
2. **Корреляция ≠ причинность** — найденные связи не доказывают причинный эффект.
3. **Просмотры — прокси охвата**, а не уникальные читатели.
4. **Алгоритмы показа** искажают выборку читателей.
5. **«Дозревающие» метрики** учтены окном 7 дней, но поздние просмотры возможны.
6. **Эвристика личных постов** (`is_personal_heur`) — без ручной разметки, возможны ошибки.
7. **Праздники** могут иметь иную природу всплесков.
8. **Выбросы** — 1 вирусный пост завышает средние.
9. **Низкий R² регрессии** — тема и качество поста в данных отсутствуют.

**Прозрачность:** данные собраны из открытого канала через официальный API Telegram (Telethon). Персональные данные читателей не собираются.

**Безопасность:**
- Файл `.env` содержит локальные креды (Postgres, `TG_API_HASH`) — он **не коммитится** и **удалён из репозитория**, чтобы не светить секреты.
- В репозитории остаётся только `.env.example` с плейсхолдерами.
- В ноутбуках/логах пароли маскируются (`engine.url.render_as_string(hide_password=True)`).
- При утечке/шаринге проекта секреты считаются скомпрометированными — смените пароль Postgres и пересоздайте `TG_API_HASH` в my.telegram.org.

  ```gitignore
  *.ipynb_checkpoints
  __pycache__/
  ```

  Если `.env` когда-то уже попадал в историю git — недостаточно просто удалить файл: нужно вычистить историю (`git filter-repo`) и **ротировать все секреты**.
